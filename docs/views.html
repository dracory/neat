Views

Neat ORM supports creating, dropping, and introspecting database views through the schema builder. View management is implemented across all supported drivers: MySQL, PostgreSQL, SQLite, SQL Server, Turso, and Oracle.

API

All view operations are methods on the schema builder (db.Schema()):

MethodDescription
CreateView(name, q)Create a view from a query builder. Bound parameters are interpolated via ToRawSql so the view definition contains no placeholder characters.
CreateViewRaw(name, selectSQL)Create a view from a raw SELECT SQL string. Empty SQL is rejected.
DropView(name)Drop a view. Returns an error if the view does not exist.
DropViewIfExists(name)Drop a view if it exists; no-op otherwise. Implemented as check-then-drop (see notes below).
HasView(name)Return true if the view exists.
GetViews()Return a list of all views in the database.
DropAllViews()Drop all views in the database.

Creating a View from a Query Builder

selectQuery := db.Query().Table("users").Where("active", true)
err := db.Schema().CreateView("active_users", selectQuery)

The query builder's ToRawSql is used (not ToSql) so that bound parameters are interpolated into the SQL string. ToSql leaves ? placeholders intact, which would produce a view definition containing literal ? characters.

Creating a View from Raw SQL

err := db.Schema().CreateViewRaw("user_summary", "SELECT user_id, COUNT(*) AS order_count FROM orders GROUP BY user_id")

The raw SQL string is passed through to the driver's CREATE VIEW statement unchanged. Empty SQL is rejected with an error.

Checking and Dropping

// Check existence
exists := db.Schema().HasView("active_users")

// Drop if it exists (safe to call unconditionally)
err := db.Schema().DropViewIfExists("active_users")

// Drop unconditionally (errors if the view does not exist)
err := db.Schema().DropView("active_users")

Schema-Qualified Names

All view methods accept schema-qualified names such as public.my_view (PostgreSQL), dbo.my_view (SQL Server), mydb.my_view (MySQL), main.my_view (SQLite), or scott.my_view (Oracle). The grammar quotes each component separately.

Per-Driver Behavior

DriverCREATE VIEW syntaxNotes
MySQLCREATE VIEWSupports DROP VIEW IF EXISTS natively.
PostgreSQLCREATE VIEWSupports DROP VIEW IF EXISTS natively.
SQLiteCREATE VIEWSupports DROP VIEW IF EXISTS natively.
SQL ServerCREATE VIEWSupports DROP VIEW IF EXISTS natively.
TursoCREATE VIEWSQLite edge; same syntax as SQLite.
OracleCREATE OR REPLACE FORCE VIEWUses OR REPLACE so re-running a migration is idempotent. FORCE allows creation even if underlying tables have compilation errors.
DropViewIfExists implementation: The schema layer's DropViewIfExists uses a check-then-drop approach (HasView then DropView) rather than driver-specific DROP VIEW IF EXISTS syntax or PL/SQL blocks. This is because the go-ora driver for Oracle cannot execute PL/SQL anonymous blocks via Exec(). The check-then-drop approach introduces a small TOCTOU race in multi-process workflows; for single-process migration workflows (the typical case) this is acceptable. For drivers that support atomic IF EXISTS, callers can use r.grammar.CompileDropViewIfExists() directly to avoid the race.

Identifier Validation

View names are validated through the same identifier-wrapping layer as table names. Injection attempts such as "users; DROP TABLE users; --" are rejected with an error before any SQL is executed.
