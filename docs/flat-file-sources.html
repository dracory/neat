Flat-File Sources

Query CSV, JSON, JSONL, and XML files directly with the full power of the ORM query builder — no manual parsing, no external dependencies. Neat ORM is the only Go ORM that lets you query flat-file data formats as if they were database tables, using the same fluent API you use for real databases.

Unique Feature: No other Go ORM supports querying CSV, JSON, JSONL, and XML files out of the box. GORM, Ent, sqlc, sqlboiler, Bun, and all other major Go ORMs require you to parse files yourself and write boilerplate to load data into a database before you can query it. Neat ORM does this in one line.

How It Works

Flat-file sources are thin wrappers around the array-backed source system. Each constructor parses a file (or raw string), infers column types, and returns an *arraysource.Model that you pass to Model(). The array driver handles the rest — SQLite table creation, row insertion, and query execution.

All parsers use only the Go standard library (encoding/csv, encoding/json, encoding/xml). No external dependencies are added.

API Overview

Function Input Format Table Name
neat.NewCsvSource(csvString, tableName) Raw CSV string CSV Explicit
neat.NewCsvFileSource(filePath) File path CSV From filename
neat.NewCsvFSSource(embedFS, filePath) Embedded FS + path CSV From filename
neat.NewCsvFileSourceWithDelimiter(filePath, delimiter) File path + delimiter TSV/PSV From filename
neat.NewJsonSource(jsonString, tableName, isJSONL) Raw JSON/JSONL string JSON / JSONL Explicit
neat.NewJsonFileSource(filePath) File path JSON / JSONL From filename
neat.NewJsonFSSource(embedFS, filePath) Embedded FS + path JSON / JSONL From filename
neat.NewXmlSource(xmlString, tableName) Raw XML string XML Explicit
neat.NewXmlFileSource(filePath) File path XML From filename
neat.NewXmlFSSource(embedFS, filePath) Embedded FS + path XML From filename

Each format has three variants: string constructors (accept raw content, require explicit table name), file constructors (accept a disk file path, derive table name from filename), and embedded filesystem (embed.FS) constructors (accept an embed.FS / fs.FS and a relative file path).

CSV Sources

Query a CSV File

type User struct {
    ID     int    `db:"id"`
    Name   string `db:"name"`
    Email  string `db:"email"`
    Active bool   `db:"active"`
}

config := neat.DBConfig{
    Default: "array_db",
    Connections: map[string]neat.ConnectionConfig{
        "array_db": {Driver: "array"},
    },
}
db, _ := neat.New(config)

var users []User
err := db.Query().
    Model(neat.NewCsvFileSource("data/users.csv")).
    Where("active = ?", true).
    OrderBy("name", "asc").
    Get(&users)

The first row of the CSV file must be a header defining column names. Column types are inferred from the data:

  • Integer — 123, -456
  • Float — 19.99, -0.5
  • Bool — true, false (stored as 0/1)
  • Datetime — RFC3339, 2006-01-02, 2006-01-02 15:04:05, 01/02/2006
  • String — everything else

Type widening applies across rows: a column with mixed int and float values becomes float; any incompatible mix becomes string.

Query a CSV String

csvString := "id,name,active\n1,Alice,true\n2,Bob,false\n"

var users []User
err := db.Query().
    Model(neat.NewCsvSource(csvString, "users")).
    Where("active = ?", true).
    Get(&users)

TSV and Custom Delimiters

err := db.Query().
    Model(neat.NewCsvFileSourceWithDelimiter("data/events.tsv", '\t')).
    Get(&events)

JSON Sources

Query a JSON File

// data/users.json:
// [{"id": 1, "name": "Alice", "active": true, "created": "2024-01-15T10:30:00Z"}, ...]

type User struct {
    ID      int       `db:"id"`
    Name    string    `db:"name"`
    Active  bool      `db:"active"`
    Created time.Time `db:"created"`
}

var users []User
err := db.Query().
    Model(neat.NewJsonFileSource("data/users.json")).
    Where("active = ?", true).
    OrderBy("name", "asc").
    Get(&users)

JSON has native types, so no string-to-type inference is needed. Values are already int64, float64, bool, string, or nil. Integer-valued floats are automatically converted to int64 so the array driver infers INTEGER columns. String values matching RFC3339 are converted to time.Time. Nested objects and arrays are stored as JSON strings (queryable via SQLite JSON functions).

Query a JSONL File

JSONL (JSON Lines) files contain one JSON object per line. The format is auto-detected from the file extension (.jsonl or .ndjson):

// data/events.jsonl:
// {"id": 1, "type": "login", "user_id": 42}
// {"id": 2, "type": "purchase", "user_id": 17, "amount": 49.99}

type Event struct {
    ID     int     `db:"id"`
    Type   string  `db:"type"`
    UserID int     `db:"user_id"`
    Amount float64 `db:"amount"`
}

var events []Event
err := db.Query().
    Model(neat.NewJsonFileSource("data/events.jsonl")).
    Where("type = ?", "purchase").
    OrderBy("id", "asc").
    Get(&events)

Query a JSON String

jsonString := `[{"id": 1, "name": "Alice", "active": true}]`

var users []User
err := db.Query().
    Model(neat.NewJsonSource(jsonString, "users", false)).
    Get(&users)

// JSONL string:
jsonlString := `{"id": 1, "type": "login"}` + "\n" + `{"id": 2, "type": "logout"}`
var events []Event
err = db.Query().
    Model(neat.NewJsonSource(jsonlString, "events", true)).
    Get(&events)

XML Sources

Query an XML File

<!-- data/users.xml -->
<users>
  <user id="1">
    <name>Alice</name>
    <email>alice@example.com</email>
    <active>true</active>
    <created>2024-01-15T10:30:00Z</created>
  </user>
  <user id="2">
    <name>Bob</name>
    <email>bob@example.com</email>
    <active>false</active>
  </user>
</users>
var users []User
err := db.Query().
    Model(neat.NewXmlFileSource("data/users.xml")).
    Where("active = ?", true).
    OrderBy("name", "asc").
    Get(&users)

XML Mapping Rules

XML is hierarchical, so the mapping to rows and columns follows these rules:

  • Root element — container, skipped (e.g., <users>)
  • Each direct child — becomes a row (e.g., each <user>)
  • Attributes — become columns (e.g., id="1" → column id)
  • Leaf sub-elements — become columns (e.g., <name>Alice</name> → column name)
  • Nested sub-elements — stored as JSON strings (e.g., <address><city>NYC</city></address> → column address with JSON value {"city":"NYC"})

Column type inference is the same as CSV: int, float, bool, time, string.

Query an XML String

xmlString := `<users>
  <user id="1"><name>Alice</name><active>true</active></user>
  <user id="2"><name>Bob</name><active>false</active></user>
</users>`

var users []User
err := db.Query().
    Model(neat.NewXmlSource(xmlString, "users")).
    Where("active = ?", true).
    Get(&users)

Type Inference

CSV and XML sources infer column types from string values. The inference tries each type in order, widening as needed:

  1. INTEGER — strconv.ParseInt succeeds
  2. REAL — strconv.ParseFloat succeeds
  3. INTEGER (bool) — true/false stored as 0/1
  4. DATETIME — RFC3339 or common date formats
  5. TEXT — fallback for everything else

Type widening across rows: INTEGER → REAL → TEXT. A column with mixed int and float values becomes REAL. Any incompatible mix becomes TEXT.

JSON sources don't need type inference — JSON has native types. Integer-valued float64 values (from encoding/json) are automatically converted to int64.

Full Query Builder Support

Since flat-file sources are array-backed sources, the full query builder API works:

  • Where, OrWhere, WhereIn, WhereNull
  • OrderBy, GroupBy, Having
  • Limit, Offset
  • Join (across multiple sources)
  • First, Get, Count, Sum, Avg, Max, Min
  • Aggregates and GROUP BY with HAVING
Note: Each Model() call with a flat-file source creates a fresh in-memory SQLite table. The table exists for the duration of that query. To query the same file multiple times, pass the same source instance or create a new one — the array driver caches populated tables per connection.

Examples

  • csv-source — query a CSV file with Where, OrderBy
  • json-source — query JSON and JSONL files
  • xml-source — query an XML file with attributes and nested elements

Comparison with Other Go ORMs

No major Go ORM supports querying flat-file formats directly. Neat ORM also offers a dedicated csvdb driver for querying an entire directory of CSV files as a database:

ORM CSV JSON JSONL XML CSV Directory
Neat ORM Yes Yes Yes Yes Yes (csvdb driver)
GORM No No No No No
Ent No No No No No
sqlc No No No No No
sqlboiler No No No No No
Bun No No No No No
Goqu No No No No No

With other ORMs, you must: (1) parse the file yourself, (2) load data into a real database, (3) then query it. Neat ORM does all three in one Model() call. For querying a directory of CSV files, the csvdb driver does it at connection open time — see CSVDB Driver.
