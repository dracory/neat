GODB (Go Data)

GODB treats native Go variables compiled into your binary as database tables. There is no file I/O and no parsing at runtime — the data is converted from Go slices into rows and inserted into an in-memory SQLite database at Open() time. This is the fastest way to query static, build-time data (lookup tables, seeded reference data, compiled-in datasets) with the full query builder API.

Connection

Tables are supplied via the Tables field on ConnectionConfig. Two config styles are supported:

Style A — Map (alphabetical order)

import "github.com/dracory/neat/database/driver"

config := neat.DBConfig{
    Default: "go_db",
    Connections: map[string]neat.ConnectionConfig{
        "go_db": {
            Driver: "godb",
            Tables: driver.Tables{
                "blogs":      data.Blogs,
                "categories": data.Categories,
            },
        },
    },
}

Map keys are sorted alphabetically so table creation order is deterministic. Use Style B if creation order matters (for example, to satisfy foreign-key constraints).

Style B — Slice (declaration order preserved)

config := neat.DBConfig{
    Default: "go_db",
    Connections: map[string]neat.ConnectionConfig{
        "go_db": {
            Driver: "godb",
            Tables: []driver.Table{
                {Name: "categories", Data: data.Categories},
                {Name: "blogs",      Data: data.Blogs},
            },
        },
    },
}

The DSN is always :memory:; the Database field is ignored.

Accepted Data Shapes

Each table's Data value can be any of:

  • []map[string]any — pre-built map rows.
  • []SomeStruct — a slice of structs. Struct fields are read via the db tag (falling back to the field name) using the shared arraysource.ConvertSliceToRows converter.
  • Any other slice — converted best-effort via the same converter.

Driver-Specific Options

  • Tables - either driver.Tables (map) or []driver.Table (slice). Any other type causes Open() to fail with a clear type error.
  • Database - ignored; the driver always opens :memory:.

Placeholder Format

GODB reports dialect sqlite and uses positional ? placeholders, identical to SQLite.

Type Mappings

Column types are inferred from the Go values via the shared array-source type inference logic. The resulting SQLite types follow the same rules as the Array driver: integers → INTEGER, floats → REAL, booleans → INTEGER, time.Time → DATETIME, strings → TEXT, []byte / json.RawMessage → BLOB. Mixed integer/real columns widen to REAL; otherwise incompatible types widen to TEXT.

Behavior Notes

  • Row limit: A single table accepts at most MaxGODBRows = 100000 rows. Larger tables return an error to prevent unbounded memory/CPU consumption.
  • Identifier validation: Table and column names are validated with isSimpleIdentifier before being interpolated into DDL to prevent SQL injection. Names must match [A-Za-z_][A-Za-z0-9_]*.
  • Table name collisions: Table names are tracked case-insensitively. Open() fails with a clear error if two configured tables would produce colliding SQLite table names.
  • Atomic population: Each table's rows are inserted in a single transaction. If any row fails to insert, the table is rolled back and Open() returns an error.
  • Build-time data: Because the data is compiled into the binary, GODB is best suited for static reference data. For data that changes between deployments, regenerate the binary or use CSVDB / JSONDB / XMLDB instead.
  • Stateless driver: All state lives in the in-memory SQLite database. The driver struct itself holds no per-connection state beyond the configured Tables, which is set once before Open().

Default Ports

GODB is embedded and in-memory — there is no network port and no file path.
