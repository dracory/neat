Turso

Turso is a SQLite-based edge database accessed over the libsql protocol. Neat ORM uses the tursodatabase/libsql-client-go driver for remote connections and falls back to the modernc.org/sqlite driver for local file:// databases. Because Turso is SQLite under the hood, the type mappings and most quirks are identical to the SQLite page.

Connection

// Remote Turso database
config := neat.DBConfig{
    Default: "turso",
    Connections: map[string]neat.ConnectionConfig{
        "turso": {
            Driver:   "turso",
            Database: "my-org-my-db.turso.io", // host/database
            Password: "your-auth-token",       // authToken in the DSN
        },
    },
}

// Local file (development / tests)
config := neat.DBConfig{
    Default: "turso",
    Connections: map[string]neat.ConnectionConfig{
        "turso": {
            Driver:   "turso",
            Database: "file:///var/data/local.db",
        },
    },
}

The DSN builder prepends libsql:// if the Database value does not already start with libsql:// or file://. When a Password is provided and the URL is not a file:// URL, it is appended as ?authToken=... (URL-encoded). Local file:// databases never receive an auth token.

Driver-Specific Options

  • Database - Turso database URL (e.g. host.turso.io) or local file:// path
  • Password - Turso auth token, appended as authToken query parameter for remote databases

Placeholder Format

Turso uses positional ? placeholders, identical to SQLite.

Type Mappings

Turso inherits the SQLite grammar. See the SQLite type mappings table for the full list. Key points:

  • All integer types collapse to integer; boolean uses tinyint(1).
  • json / jsonb map to text. Use the json1 extension functions to query JSON at runtime.
  • No spatial types are emitted by the grammar.
  • dateTimeTz and timestampTz map to plain datetime.

Quirk: Turso supports embedded replicas - a local file:// database that syncs to a remote primary. To use this mode, pass a file:// DSN with the appropriate libsql query parameters (authToken, syncUrl, etc.) directly via the Dsn field rather than letting Neat ORM build the DSN.

Quirk: The integration test helper falls back to sqlite://:memory:?multi_stmts=true when TURSO_URL and TURSO_AUTH_TOKEN are not set. This means tests run against pure SQLite unless a real Turso endpoint is configured, which is convenient for CI but does not exercise the libsql network protocol.

Quirk: Some SQLite features available locally (e.g. certain PRAGMAs, custom functions) may behave differently or be unavailable on the remote Turso endpoint. Test against the same deployment target you plan to use in production.

Behavior Notes

  • Concurrency: Remote Turso databases handle concurrent reads and serialized writes server-side. Local file:// databases follow SQLite's normal concurrency rules.
  • Foreign keys: Foreign key enforcement follows SQLite defaults - off unless PRAGMA foreign_keys = ON is set per connection.
  • Transactions: Savepoints are supported, inherited from SQLite.
  • Schema migrations: Schema changes are subject to SQLite's DDL rules. Turso replicates schema changes to replicas automatically.

Default Ports

  • Remote Turso: HTTPS (443) to *.turso.io
  • Local file: no port (embedded)
