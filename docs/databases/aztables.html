Azure Table Storage

Azure Table Storage is a NoSQL key-value/entity store provided by Microsoft Azure. Neat ORM supports Azure Table Storage through the aztables driver powered by github.com/dracory/aztablessql, which translates a supported subset of SQL into Azure Table Storage REST/OData queries.

Connection

To connect to Azure Table Storage, configure the connection with Driver: "aztables" and provide a valid Azure Storage connection string in the Dsn field:

// Azure Table Storage production connection
config := neat.DBConfig{
    Default: "aztables",
    Connections: map[string]neat.ConnectionConfig{
        "aztables": {
            Driver: "aztables",
            Dsn:    "DefaultEndpointsProtocol=https;AccountName=myaccount;AccountKey=mykey;TableEndpoint=https://myaccount.table.core.windows.net/;",
        },
    },
}

db, err := neat.New(config)
if err != nil {
    log.Fatal(err)
}
defer db.Close()

You can also create a connection directly using DSN helper constructors:

// Connect via DSN
db, err := neat.NewFromDSN("DefaultEndpointsProtocol=https;AccountName=myaccount;AccountKey=mykey;TableEndpoint=https://myaccount.table.core.windows.net/;")

// Or using the aztables constructor
db, err := neat.NewAztables("DefaultEndpointsProtocol=https;AccountName=myaccount;AccountKey=mykey;TableEndpoint=https://myaccount.table.core.windows.net/;")

Local Emulator (Azurite)

For local development and testing, you can run Microsoft's official Azurite emulator (e.g. via Docker) and pass the emulator connection string:

config := neat.DBConfig{
    Default: "aztables",
    Connections: map[string]neat.ConnectionConfig{
        "aztables": {
            Driver: "aztables",
            Dsn:    "DefaultEndpointsProtocol=http;AccountName=devstoreaccount1;AccountKey=Eby8vdM02xNOcqFlqUwJPLlmEtlCDXJ1OUzFT50uSRZ6IFsuFq2UVErCz4I6tq/K1SZFPTOtr/KBHBeksoGMGw==;TableEndpoint=http://127.0.0.1:10002/devstoreaccount1;",
        },
    },
}

Driver-Specific Options

  • Dsn — Azure Storage connection string containing AccountName, AccountKey, and TableEndpoint (required)

Placeholder Format

The aztables driver uses positional ? placeholders, identical to MySQL and SQLite.

Primary Keys & Partitioning

Azure Table Storage requires every entity to have a PartitionKey and a RowKey. In Neat ORM models targeting Azure Table Storage, define these two fields as string columns:

type Product struct {
    PartitionKey string `db:"PartitionKey"`
    RowKey       string `db:"RowKey"`
    Name         string `db:"Name"`
    Price        float64 `db:"Price"`
}

Supported Features

  • CRUD Operations: Create, First, Get, Update, and Delete
  • Filtering: Where clauses with comparison operators (=, !=, >, >=, <, <=) combined with AND
  • Projections & Aggregates: Select column projections and COUNT(*)
  • Pagination: Limit clause for bounding query result sets

Quirk: Identifier Quotes. The aztablessql SQL parser expects raw unquoted identifiers (e.g., [A-Za-z0-9_]+). Neat ORM automatically omits identifier quoting when generating SQL for the aztables dialect.

Quirk: Transactions. Multi-partition SQL transactions (BEGIN / COMMIT) are not supported by Azure Table Storage and return a "transactions not supported" error. Atomic batch operations within a single partition are available through the native aztablessql batch API.

Quirk: Unsupported Clauses. Azure Table Storage is a NoSQL key-value store and does not support relational features such as JOIN, GROUP BY, UNION, subqueries, or OFFSET. Neat ORM's query builder automatically strips OFFSET when generating SQL for the aztables dialect.

Azure Cosmos DB for Table Compatibility

The aztables driver is fully compatible with Azure Cosmos DB for Table. To use Cosmos DB for Table, point the TableEndpoint in your connection string to your Cosmos DB Table API endpoint.

Default Ports

  • Azure Table Storage (HTTPS): 443
  • Azurite Emulator (HTTP Table endpoint): 10002
