JSONDB (JSON Directory)

JSONDB turns a directory of .json, .jsonl, and .ndjson files into a queryable database. Each file becomes a table named after the file (without the extension); object keys define the columns. Under the hood the driver opens an in-memory SQLite database and populates it at Open() time, so you get the full query builder — including JOINs across JSON, JSONL, and NDJSON files — with no external dependencies (parsing uses only the Go standard library encoding/json).

For the higher-level neat.NewJsonSource helper that loads a single JSON/JSONL string into any database, see Flat-File Sources.

Connection

config := neat.DBConfig{
    Default: "json_db",
    Connections: map[string]neat.ConnectionConfig{
        "json_db": {
            Driver:   "jsondb",
            Database: "/path/to/json/dir", // directory containing .json/.jsonl/.ndjson files
        },
    },
}

db, err := neat.New(config)
if err != nil { ... }
defer db.Close()

The Database field is the directory path. If it is empty or :memory:, no directory is scanned and an empty in-memory SQLite database is returned (useful for tests that add tables later).

Directory Layout

/path/to/json/dir/
    users.json       # becomes table "users"  (array of objects)
    products.json    # becomes table "products"
    orders.jsonl     # becomes table "orders"  (one object per line)
    events.ndjson    # becomes table "events"  (alias for JSONL)

Each file's object keys define the column names. Column types are inferred from the JSON values (see Type Inference below).

Driver-Specific Options

  • Database - directory path containing .json, .jsonl, or .ndjson files, or empty / :memory: for an empty in-memory database.
  • FS - optional embed.FS or fs.FS instance for querying embedded JSON directory files compiled into the Go binary.

Embedded Filesystem (embed.FS)

//go:embed data/*.json
var jsonFS embed.FS

config := neat.DBConfig{
    Default: "json_db",
    Connections: map[string]neat.ConnectionConfig{
        "json_db": {
            Driver:   "jsondb",
            Database: "data", // relative path inside jsonFS
            FS:       jsonFS,
        },
    },
}

Placeholder Format

JSONDB reports dialect sqlite and uses positional ? placeholders, identical to SQLite.

Type Inference

Column types are inferred from the JSON values by the shared array-source type inference logic. The resulting SQLite types follow the same rules as the Array driver: JSON numbers without a fractional part → INTEGER, JSON numbers with a fractional part → REAL, JSON booleans → INTEGER, strings → TEXT, nested objects/arrays → BLOB (stored as the raw JSON bytes). Mixed integer/real columns widen to REAL; otherwise incompatible types widen to TEXT.

Quirk: JSON object keys are not required to be uniform across rows. A column that appears in some objects but not others is still created; missing values become SQL NULL. Columns that are null in every row default to TEXT.

Behavior Notes

  • File selection: Only top-level files ending in .json, .jsonl, or .ndjson (case-insensitive extension) are loaded. Subdirectories are skipped.
  • Table name collisions: Table names are tracked case-insensitively. On case-insensitive filesystems (Windows, macOS default) where Users.json and users.json would produce colliding SQLite table names, Open() fails with a clear error rather than silently overwriting one table with another.
  • Stateless driver: All state lives in the in-memory SQLite database. The driver struct itself holds no per-connection state, so a single driver instance can be shared across connections.
  • Read-only data: The directory is read once at Open(). Changes to the JSON files after the connection is opened are not reflected. Re-open the connection to pick up file changes.
  • Single connection: Like the other embedded drivers, JSONDB is pinned to a single underlying *sql.DB (no connection pooling across separate in-memory databases).

Default Ports

JSONDB is embedded — there is no network port. The "address" is a filesystem directory path or :memory:.
