Supported Databases

Database-specific quirks, type mappings, and configuration notes for each backend supported by Neat ORM

One ORM, Many Backends

Neat ORM ships with first-class drivers for six databases and is wire-compatible with several more. Each backend has its own dialect, placeholder style, type mappings, and edge cases. Use the per-database pages below to understand the quirks before you deploy.

First-Class Drivers
Wire Protocol

MySQL

Primary SQL backend. Also drives MariaDB and TiDB via the MySQL wire protocol.

 Wire Protocol

PostgreSQL

Advanced type system with JSONB, arrays, and PostGIS geometry. Drives CockroachDB and YugabyteDB.

 Embedded

SQLite

Embedded file-based database. Great for tests, prototypes, and single-process workloads.

 Wire Protocol

SQL Server

Microsoft SQL Server with named placeholders and nvarchar-based text storage.

 Wire Protocol

Oracle

Enterprise database with NUMBER-based typing, CLOB for text, and SDO_GEOMETRY for spatial data.

 Edge / Cloud

Turso

SQLite-based edge database over the libsql protocol. Local file or remote replica.
Wire-Compatible Databases
MySQL-Compatible

TiDB

Distributed SQL with high MySQL compatibility. Notable divergences in spatial types, savepoints, and locking.

 MySQL-Compatible

MariaDB

Nearly 100% MySQL-compatible. Uses the MySQL driver directly. See the MySQL page for notes.

 PostgreSQL-Compatible

CockroachDB

Distributed PostgreSQL-compatible database. Uses the PostgreSQL driver. See the PostgreSQL page for notes.

 PostgreSQL-Compatible

YugabyteDB

Distributed PostgreSQL-compatible database. Uses the PostgreSQL driver. See the PostgreSQL page for notes.
