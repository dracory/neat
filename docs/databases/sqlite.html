SQLite

SQLite is the embedded, file-based (or in-memory) backend. Neat ORM uses the pure-Go modernc.org/sqlite driver, so no CGO is required. SQLite is ideal for tests, prototypes, single-process services, and the local side of Turso.

Connection

// In-memory database
dsn := "sqlite://:memory:?multi_stmts=true"
db, err := neat.NewFromDSN(dsn)

// File-based database
config := neat.DBConfig{
    Default: "sqlite",
    Connections: map[string]neat.ConnectionConfig{
        "sqlite": {
            Driver:   "sqlite",
            Database: "/var/data/app.db", // file path; empty = :memory:
        },
    },
}

If Database is empty, Neat ORM defaults to :memory:. The multi_stmts=true query parameter enables multi-statement execution, which is required for some schema operations.

Driver-Specific Options

  • Database - file path, or empty for an in-memory database

Placeholder Format

SQLite uses positional ? placeholders, identical to MySQL.

Type Mappings

SQLite uses a flexible type affinity system. Most blueprint types collapse to a small set of storage classes:

Blueprint TypeSQLite Type
bigInteger / integer / mediumInteger / smallInteger / tinyIntegerinteger
booleantinyint(1)
char / string / tinyTextvarchar / text
date / dateTime / dateTimeTz / timestamp / timestampTzdatetime (or date for date)
decimalnumeric
double / floatdouble / float
enumvarchar check ("col" in (...))
json / jsonbtext
longText / mediumText / texttext
time / timeTztime

Quirk: SQLite has no native JSON type. json and jsonb both produce a text column. Use the json1 extension functions (compiled in by default) to query JSON values at runtime.

Quirk: SQLite has no dedicated tinyint, mediumint, or bigint storage class. All integer blueprint types map to integer, which uses 1, 2, 3, 4, 6, or 8 bytes depending on the value. The exception is boolean, which maps to tinyint(1) for compatibility with drivers that special-case that declaration.

Quirk: dateTimeTz and timestampTz map to the same datetime type as their non-Tz counterparts. SQLite has no timezone-aware datetime type; timezone handling is the application's responsibility.

Quirk: enum is emulated with a check constraint on a varchar column. SQLite enforces check constraints at write time.

Quirk: SQLite has no spatial types. Blueprint calls for geometry, point, polygon, etc. are not mapped by the SQLite grammar and will produce empty type strings. Use a geometry extension such as SpatiaLite if you need spatial support.

Behavior Notes

  • Concurrency: SQLite serializes writes. For concurrent test runs, use separate in-memory databases per test or enable WAL mode on file-based databases.
  • Foreign keys: Foreign key enforcement is off by default in SQLite. Enable it per connection with PRAGMA foreign_keys = ON; if you rely on FK constraints.
  • Auto-increment: INTEGER PRIMARY KEY columns auto-increment. The AUTOINCREMENT keyword is rarely needed and imposes a small overhead.
  • Transactions: Savepoints are supported natively (SAVEPOINT name).
  • DDL in transactions: SQLite allows schema changes inside a transaction, which is useful for test setup and teardown.

Default Ports

SQLite is embedded - there is no network port. The "address" is a file path or :memory:.
