SQL Server

Microsoft SQL Server is supported via the microsoft/go-mssqldb driver. The schema builder targets datetime2 and nvarchar for improved Go compatibility.

Connection

config := neat.DBConfig{
    Default: "sqlserver",
    Connections: map[string]neat.ConnectionConfig{
        "sqlserver": {
            Driver:   "sqlserver",
            Host:     "127.0.0.1",
            Port:     1433,
            Database: "test",
            Username: "sa",
            Password: "YourStrong@Passw0rd",
        },
    },
}

The DSN is built as a URL: sqlserver://user:pass@host:port?database=db. Validation requires Host and Database; Username is optional when using Windows authentication.

Driver-Specific Options

  • No driver-specific options are currently exposed on ConnectionConfig. SSL and encryption are controlled via the DSN string if you pass Dsn directly.

Placeholder Format

SQL Server uses named placeholders @p1, @p2, @p3, ... The placeholder index is generated from the bind position.

Quirk: All text types use the Unicode nvarchar / nchar family, not the ASCII varchar / char. This avoids data loss for non-Latin characters but doubles storage for ASCII-only data.

Quirk: timestamp maps to datetime2, not the SQL Server timestamp type (which is a row version, not a datetime). datetime2 has a wider range (0001-9999) than the legacy datetime (1753-9999), which is important for Go's time.Time zero value.

Quirk: timestampTz maps to datetimeoffset, which stores the timezone offset alongside the value. timeTz maps to plain time because SQL Server has no timezone-aware time type.

Quirk: SQL Server has no native JSON type. json and jsonb both produce nvarchar(max). Use JSON_VALUE, JSON_QUERY, and ISJSON to work with JSON content at runtime.

Quirk: The SQL Server grammar does not define spatial types (geometry, point, etc.). SQL Server does ship a geometry type, but the schema builder does not currently emit it.

Behavior Notes

  • Identifiers: SQL Server uses square brackets [name] for quoting. Neat ORM handles this automatically.
  • Auto-increment: Use IDENTITY columns. The schema builder emits IDENTITY(1,1) for auto-incrementing integer columns.
  • Database creation: The test database is not created automatically by the Docker image. Create it manually with sqlcmd before running integration tests.
  • Locking: LockForUpdate() emits WITH (UPDLOCK, ROWLOCK); SharedLock() emits WITH (HOLDLOCK, ROWLOCK).
  • Default timestamps: useCurrent() sets DEFAULT CURRENT_TIMESTAMP. SQL Server has no native ON UPDATE equivalent; useCurrentOnUpdate() requires a trigger.

Default Ports

  • SQL Server: 1433
