CSVDB (CSV Directory)

CSVDB turns a directory of .csv files into a queryable database. Each CSV file becomes a table named after the file (without the .csv extension); the first row of each file is the header. Under the hood the driver opens an in-memory SQLite database and populates it at Open() time, so you get the full query builder — including JOINs across CSV files — with no external dependencies.

For the higher-level neat.NewCsvSource / neat.NewCsvFileSource helpers that load a single CSV string or file into any database, see Flat-File Sources.

Connection

config := neat.DBConfig{
    Default: "csv_db",
    Connections: map[string]neat.ConnectionConfig{
        "csv_db": {
            Driver:   "csvdb",
            Database: "/path/to/csv/dir", // directory containing .csv files
        },
    },
}

db, err := neat.New(config)
if err != nil { ... }
defer db.Close()

The Database field is the directory path. If it is empty or :memory:, no directory is scanned and an empty in-memory SQLite database is returned (useful for tests that add tables later).

Directory Layout

/path/to/csv/dir/
    users.csv       # becomes table "users"
    products.csv    # becomes table "products"
    orders.csv      # becomes table "orders"

Each file's first row is the header and defines the column names. Subsequent rows are the data. Column types are inferred from the CSV values (see Type Inference below).

Driver-Specific Options

  • Database - directory path containing .csv files, or empty / :memory: for an empty in-memory database.
  • FS - optional embed.FS or fs.FS instance for querying embedded CSV directory files compiled into the Go binary.

Embedded Filesystem (embed.FS)

//go:embed data/*.csv
var csvFS embed.FS

config := neat.DBConfig{
    Default: "csv_db",
    Connections: map[string]neat.ConnectionConfig{
        "csv_db": {
            Driver:   "csvdb",
            Database: "data", // relative path inside csvFS
            FS:       csvFS,
        },
    },
}

Placeholder Format

CSVDB reports dialect sqlite and uses positional ? placeholders, identical to SQLite.

Type Inference

Column types are inferred from the CSV cell values by the shared array-source type inference logic. The resulting SQLite types follow the same rules as the Array driver: integers → INTEGER, floats → REAL, booleans → INTEGER, dates/times → DATETIME, everything else → TEXT. Mixed integer/real columns widen to REAL; otherwise incompatible types widen to TEXT.

Quirk: CSV is a text-only format, so numeric and boolean inference depends on the cell contents matching the expected patterns. A column that mixes 42 and 42.0 widens to REAL; a column that mixes 42 and abc widens to TEXT.

Behavior Notes

  • File selection: Only top-level files ending in .csv (case-insensitive) are loaded. Subdirectories are skipped.
  • Table name collisions: Table names are tracked case-insensitively. On case-insensitive filesystems (Windows, macOS default) where Users.csv and users.csv would produce colliding SQLite table names, Open() fails with a clear error rather than silently overwriting one table with another.
  • Stateless driver: All state lives in the in-memory SQLite database. The driver struct itself holds no per-connection state, so a single driver instance can be shared across connections.
  • Read-only data: The directory is read once at Open(). Changes to the CSV files after the connection is opened are not reflected. Re-open the connection to pick up file changes.
  • Single connection: Like the other embedded drivers, CSVDB is pinned to a single underlying *sql.DB (no connection pooling across separate in-memory databases).

Default Ports

CSVDB is embedded — there is no network port. The "address" is a filesystem directory path or :memory:.
