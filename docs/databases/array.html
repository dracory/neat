Array (In-Memory)

The array driver treats in-memory Go data as database tables. It embeds the SQLite driver and populates an in-memory SQLite database on demand the first time a model is queried. This is useful for static lookup data (statuses, countries, roles), mocking data in tests, or querying computed datasets with the full query builder API.

For the full source-constructor API (slices of structs, map rows, explicit schemas, multi-table JOINs), see the dedicated Array-Backed Sources page. This page covers the driver-specific behavior, type inference, and limits.

Connection

The simplest entry point is neat.NewMemoryDB() — zero configuration, no DBConfig, no connection map:

db, err := neat.NewMemoryDB()
if err != nil { ... }
defer db.Close()

For full control, use the explicit config approach with the array driver name:

config := neat.DBConfig{
    Default: "memory",
    Connections: map[string]neat.ConnectionConfig{
        "memory": {
            Driver: "array",
        },
    },
}

The DSN is built the same way as SQLite (in-memory :memory:). The Database field is ignored — the array driver always uses an in-memory database.

How Population Works

Unlike the CSVDB, JSONDB, XMLDB, and GODB drivers — which populate tables at Open() time — the array driver populates lazily. The first time Model() is called with a value implementing the ArraySource interface, the driver:

  1. Acquires a per-table mutex (keyed by *sql.DB pointer + table name).
  2. Checks a sync.Map to see if the table has already been populated for this connection.
  3. If not, infers the schema (or uses an explicit schema if provided), creates the table, and inserts all rows in a transaction.
  4. Marks the table as populated so subsequent queries skip the population step.

This means the same in-memory database can host multiple array sources, and JOINs across them work as long as each model is registered before it is queried.

Driver-Specific Options

  • Database - ignored; the driver always opens :memory:.

Placeholder Format

The array driver reports dialect array but uses the same positional ? placeholders as SQLite. The query builder treats array as a SQLite-family dialect.

Type Mappings

When no explicit schema is provided, the driver infers SQLite column types from the Go values in the source rows:

Go TypeSQLite Type
int, int8, int16, int32, int64, uint*INTEGER
float32, float64REAL
boolINTEGER (0/1)
time.Time, *time.TimeDATETIME
stringTEXT
[]byte, json.RawMessageBLOB

Type widening across rows follows SQLite affinity rules:

  • INTEGER + REAL in the same column → REAL.
  • Any other incompatible combination → TEXT.
  • Columns that are nil in every row default to TEXT.

Quirk: Unsupported value types (e.g. nested maps, slices other than []byte) cause Populate to fail with unsupported type … in array source. Flatten or serialize such values before passing them in.

Behavior Notes

  • Row limit: A single Populate call accepts at most MaxArrayRows = 100000 rows. Larger sources return an error to prevent unbounded memory/CPU consumption.
  • Identifier validation: Table and column names are validated with isSimpleIdentifier before being interpolated into DDL to prevent SQL injection. Names must match [A-Za-z_][A-Za-z0-9_]*.
  • Explicit schema: If the source implements ArraySchema, the provided schema is used as-is and any row key not present in the schema is rejected.
  • Existing tables: If a table with the same name already exists in the in-memory database, population is skipped (the existing schema is preserved). This guards against CREATE TABLE IF NOT EXISTS silently succeeding with a different schema.
  • Connection lifecycle: Population state is keyed by *sql.DB pointer. Stale entries are cleared by Orm.Close() → Database.Close(). If you close a *sql.DB obtained via NewFromSQLDB without calling Database.Close(), stale entries may remain; the affected query will then fail with a clear no such table error.
  • Concurrency: Per-table mutexes serialize population for the same table on the same connection. Different tables populate in parallel.

Default Ports

The array driver is embedded and in-memory — there is no network port and no file path.
