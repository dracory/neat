Array-Backed Sources

The array driver lets you query in-memory data as if it were a database table. This is useful for static lookup data (statuses, countries, roles), mocking data in tests, or querying computed datasets with the full query builder API.

Constructor Family

Neat provides three constructors for array-backed sources, in order of ergonomics:

  • neat.NewArraySourceFrom[T](items []T) — primary entry point. Accepts a slice of structs or []map[string]any. Table name is auto-generated, schema is inferred from the data.
  • neat.NewArraySource(rows []map[string]any) — accepts pre-built map rows. Use .Table("name") to override the auto-generated table name.
  • neat.NewArraySourceWithSchema(rows, schema) — accepts pre-built map rows plus an explicit column-type schema. Use this when the dataset is empty (the other constructors panic on empty slices).

Quick Start: Slice of Structs

type Status struct {
    ID    int    `db:"id"`
    Name  string `db:"name"`
    Color string `db:"color"`
}

statuses := []Status{
    {ID: 1, Name: "Pending",  Color: "yellow"},
    {ID: 2, Name: "Active",   Color: "green"},
    {ID: 3, Name: "Inactive", Color: "red"},
}

config := neat.DBConfig{
    Default: "array_db",
    Connections: map[string]neat.ConnectionConfig{
        "array_db": {Driver: "array"},
    },
}
db, _ := neat.New(config)

var results []Status
err := db.Query().
    Model(neat.NewArraySourceFrom(statuses)).
    Where("name = ?", "Active").
    OrderBy("id", "asc").
    Get(&results)

No custom ArraySource struct, no TableName() method, no Rows() method, no map[string]any literals. The table name is auto-generated from the struct type and the column schema is inferred from the data.

Quick Start: Slice of Maps

mapData := []map[string]any{
    {"id": 1, "name": "Pending", "color": "yellow"},
    {"id": 2, "name": "Active",  "color": "green"},
}

var results []Status
err := db.Query().
    Model(neat.NewArraySourceFrom(mapData)).
    OrderBy("id", "asc").
    Get(&results)

Map rows are shallow-copied at call time, so mutating the caller's maps after constructing the source does not affect the snapshot.

Custom Table Name

err := db.Query().
    Model(neat.NewArraySource(mapData).Table("statuses")).
    OrderBy("id", "asc").
    Get(&results)

Override the auto-generated table name when you need a specific name for JOINs, raw SQL, or more readable error messages.

Empty Datasets

NewArraySourceFrom panics on empty slices — there is no data to infer the schema from. Use NewArraySourceWithSchema instead:

rows := []map[string]any{}
schema := map[string]string{
    "id":    "integer",
    "name":  "text",
    "color": "text",
}
src := neat.NewArraySourceWithSchema(rows, schema)

Field Resolution

For struct slices, field names are resolved to column names using the same tag convention as the ORM, in priority order:

  1. db tag
  2. neat tag
  3. gorm tag
  4. snake_case of the Go field name

Additional rules:

  • Embedded structs are flattened.
  • Association fields (slices, struct pointers) are skipped — only scalar columns are emitted.
  • Nullable pointer fields (*string, *int) are dereferenced; nil pointers become NULL.
  • time.Time fields are included as-is.
  • Fields tagged db:"-", neat:"-", or gorm:"-" are skipped.
Note: The array driver is backed by an in-memory SQLite table. The full query builder API — Where, OrderBy, Join, GroupBy, Having, aggregates, etc. — works against array sources exactly as it does against regular database tables.

Legacy Interface (Still Supported)

The original interface-based approach is still available for cases where you need full control over the source:

type StatusSource struct{}

func (s *StatusSource) TableName() string { return "statuses" }

func (s *StatusSource) Rows() ([]map[string]any, error) {
    return []map[string]any{
        {"id": 1, "name": "Pending", "color": "yellow"},
        {"id": 2, "name": "Active",  "color": "green"},
    }, nil
}

err := db.Query().Model(&StatusSource{}).Get(&results)

NewArraySourceFrom is preferred for new code since it requires no boilerplate.

Flat-File Sources

Neat ORM also provides flat-file source constructors that parse CSV, JSON, JSONL, and XML files and return *arraysource.Model instances — the same type returned by the constructors above. This means you can query flat-file data with the full query builder API without writing any parsing code:

// Query a CSV file
db.Query().Model(neat.NewCsvFileSource("data/users.csv")).Get(&users)

// Query a JSON file
db.Query().Model(neat.NewJsonFileSource("data/products.json")).Get(&products)

// Query an XML file
db.Query().Model(neat.NewXmlFileSource("data/orders.xml")).Get(&orders)

See the Flat-File Sources page for full documentation.
